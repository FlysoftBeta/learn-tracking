# 学习app（Housekeeper）

范围：学习 app 的功能、工程进度、前端、布局与交互需求。

## 当前进度（2026-09-18）

用户报告 app 已成型，已连接 Termux，具有 Rust daemon，以及类似 VS Code 的文件编辑器和终端。智学网相关接口的抓包也已于较早前完成。

## 产品定位

- Housekeeper 主要提供一个可运行 AI、撰写文档和处理文件的 computer 环境，而不是完整编码环境。
- 文件工作区只需服务单一工作上下文，不需要多项目管理。
- Housekeeper 计划直接替代 launcher。大量功能直接内置；内置功能与外置应用采用相近的访问逻辑，逐步形成统一体验与深度集成，并有望最终替代更多第三方 app。具体替代范围和迁移计划尚未确定。

## 运行约束

- 强制依赖 Termux，不要求独立运行。
- Termux 与 Housekeeper 各自负责哪些运行时、文件、进程和生命周期管理，尚待确定。

## 前端需求

- 用 Codex app server 建立经典 Chat UI，支持模型选择、强度选择 slider 和图片上传。
- ChatGPT Web 可常驻后台，并提供快速唤起。
- 提供快速 Google Search。ChatGPT Web 与搜索都以快速获得答案为目的，共用一个简易内置浏览器；浏览器所需的登录、标签页和页面能力尚待确定。

## UI 与布局需求

- 折叠不常用内容，整体布局紧凑，适合横屏平板使用。
- 编辑器的底部／右侧面板根据可用空间展开：空间不足时采用抽屉式浮层；空间充足时参与正常布局、占据空间，而非悬浮 flyout。
- 可尝试以 panel 为核心组织 UI。具体面板层级、切换方式，以及它与 launcher 式入口和既有响应式 drawer 规则的关系尚待设计。

## 内置功能

### 文档阅读器

主要处理智学网作业中的教学资料：将老师下发的多种格式内容统一转换为 PDF 后阅读，以获得一致体验，不需要编辑功能。转换后的教学文档还会进入[外置记忆项目](../外置记忆项目/README.md)，用于检索和学习进度追踪。

需进一步明确输入格式、转换发生在本地还是服务端，原文件与转换产物的保存策略，以及进入记忆系统时采用的元数据和进度模型。

### 智学网作业界面

- 闲时自动缓存作业内容和文件，实现秒开。
- 不在 Housekeeper 内实现常规做作业功能；需要作答时跳转到智学网 app。
- 英语听说练习中的中译英、英译中环节例外：可点击“一键帮做”。用户认为这些练习价值低、手工完成浪费时间。
- 相关接口抓包已在较早前完成；这是用户报告的既有进展，尚未核对当前接口是否变化。

## 待明确的问题

- 内置功能与外置应用“访问逻辑相近”具体指统一搜索、统一卡片／图标入口，还是相同的窗口与返回逻辑？
- panel 化 UI 的主导航、同时可见面板数量和窄屏行为是什么？
- Termux 与 Housekeeper 的职责边界及故障恢复方式是什么？
- 简易内置浏览器需要保留哪些会话、登录和多页面能力？
- 文档转换应支持哪些教师常用格式，如何处理版式或字体不兼容？教学文档进入记忆系统时如何切分、索引和表示学习进度？
- 智学网缓存的刷新、过期和空间策略是什么？跳转官方 app 时是否需要定位到具体作业？“一键帮做”是否需要提交前确认？
